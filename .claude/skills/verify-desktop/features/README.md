# Desktop の機能テストの地図

この地図が Desktop の機能テストの元になる。Desktop を動かす前にこの索引を読み、該当する機能のファイルを手順として使う。対応表は `desktop.md` 6章 (検証の仕方) と台帳 (`ledger.md`) にある。

## 前提 (ベースライン)

- 実機: Arch Linux が段階5の構成で入り、niri にログインしている。dotfiles はリポジトリの `docs/platform-desktop` ブランチを取り出している。
- `docs/platform/desktop/functional/dv doctor` が fail を出さない。
- 代わりの環境: root で network namespace を作れる Linux。`ip`、`nft`、`python3`、`curl` が要る。
- この検証の実行が起動したものでない環境は、動かさない。

## 動かし方の約束

- 各手順は、ベースラインの状態から始める。
- コマンドは書いてあるとおりに使う。引用符で囲んだ名前やフラグを変えない。
- 状態を変える手順 (宣言の追加、巻き戻し) は、終わったら元に戻す。証拠は消さない。

## 証拠と skip

- 利用者の操作と、その結果の状態の両方を残す。最後の画面だけでは足りない。
- 届く・届かないの証拠には、送り元、宛先、コマンド、HTTP のコード (つながらなければ 000) を含める。
- 人の操作が要る手順は、操作した時刻と、見た画面 (写真かスクリーンショット) を証拠のフォルダに置く。
- 届かない経路は、試したコマンドと満たせなかった前提を書いて skip にする。別の経路で確かめたものを、その経路の PASS として書かない。

## 機能の書き方

各ファイルは H1 の題と、利用者から見た振る舞いを述べる1段落で始める。その後に、次の4つの H2 をこの順で置く。

1. `Sub-features`
2. `How to get to it (user POV)`
3. `Driving it with dv`
4. `Gotchas`

## 機能

- [作業面](./workspace.md): ログイン、2画面 144Hz、日本語入力、クリップボード、スクリーンショット、画面共有、niri 設定の層。
- [推論 API](./inference.md): 届く相手と届かない相手、OpenAI 互換、API キー、VRAM。
- [巻き戻し](./rollback.md): 動いた印、ブートメニューからの復元、15分の訓練、押し出しを止めるフック。
- [宣言の適用](./declare-apply.md): パッケージを足して分単位で使えること、宣言されていない状態の一覧。
- [ゼロからの再現](./install-from-zero.md): by-id で消去先を確かめること、1時間以内の再現。
