# ADR-0007: Secure Boot は無効にし、ディスクは暗号化しない

日付: 2026-10-24。状態: 承認 (2026-10-24)。

## 文脈

- G-HW-7: Secure Boot は今は有効で、無効にもできる。本文の制約に、Secure Boot もディスク暗号化も求めるものは無い。
- Arch の公式 ISO は Secure Boot で起動できない。インストールのときは、どのみち一度無効にする必要がある (Arch wiki)。
- Limine は 11.2 以降、Secure Boot が有効だと設定のチェックサムの登録を強制する。登録を忘れると起動できなくなり、Secure Boot を切っても直らない (Arch wiki / CachyOS wiki)。limine-snapper-sync はスナップショットのたびに設定を書き換えるので、この失敗の機会が増える [推論]。
- 自分の鍵だけを登録すると、GPU の Option ROM が Microsoft の鍵で署名されている機種では起動しなくなることがある (Arch wiki)。
- ディスク暗号化が守るのは、電源を切った状態でディスクを持ち出されたとき (盗難、廃棄、修理) である。このマシンに顧客情報は置かない。ただし資格情報は置かれる: age の秘密鍵、Tailscale のノード鍵、SSH 鍵、GitHub のトークン、エージェント CLI の API トークン、ブラウザのセッション。

## 決定

1. Secure Boot は**無効にする**。インストールのときに無効にし、そのまま運用する。
2. ディスクは**暗号化しない**。持ち出しへの備えは次の2つで代える。
   - **盗難のとき:** 資格情報の失効手順書 (`runbooks/credential-revocation.md`) に従い、すべて失効・交換する。
   - **廃棄・譲渡・修理に出すとき:** NVMe と HDD を sanitize で消す。消去は ADR-0006 の入口 (`wipe_declared`) を通す。

## 満たす制約 / 満たせない制約

本文の制約には直接かからない。間接的には次の2つに効く。

- REL-1 / ADR-0002: Limine のチェックサムの登録忘れで起動できなくなる経路をなくせる。
- SAF: ファームウェアの鍵を書き換えずに済むので、Option ROM で起動しなくなる危険を避けられる。

## トレードオフ

- **得るもの:**
  - インストールと巻き戻しの経路が単純になる。
  - 起動のたびにパスフレーズを入れなくて済む。
- **失うもの:**
  - ブートチェーンの改ざんを検出できない。
  - ディスクを盗まれると、資格情報は読まれる前提になる。最も被害が大きいのは Tailscale のノード鍵 (tailnet に入って Server に届く) と age の秘密鍵 (公開リポジトリの秘密情報がすべて読める)。失効手順書で、気づいてから短い時間で無効にする。

## 切り替えトリガー

| 条件 | 切り替え先 |
|---|---|
| このマシンに顧客情報や、失効できない秘密 (失効の仕組みが無い鍵) を置くことになる | LUKS でルートを暗号化する。この ADR と ADR-0002 (ESP の外を暗号化) を書き直す |
| Secure Boot を求める制約を足す | sbctl で鍵を登録する (`-m` で Microsoft の鍵を残す)。Limine の設定チェックサムを limine-snapper-sync の更新に連動させ、D-V1 のモデルに「チェックサム不一致で起動しない」状態を足して検証し直す |
