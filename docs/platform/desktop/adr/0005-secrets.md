# ADR-0005: 秘密情報は age で暗号化して git に置く

日付: 2026-10-24。状態: 承認 (2026-10-24)。

## 文脈

- 今の dotfiles は agenix (`nix-config/secrets/*.age`) で秘密情報を扱っている。agenix は NixOS のモジュールなので、ADR-0001 (Arch) では使えない。
- Desktop で要る秘密情報は次のとおり。
  - Tailscale の認証鍵 (初回だけ使う)
  - 推論 API の鍵 (ADR-0003)
  - エージェント CLI の資格情報
  - restic のパスワード (ADR-0004)

## 決定

1. **暗号化の形式は age** にする (extra の `age`)。agenix と同じ形式なので、今ある `*.age` は受け手を足して再暗号化すれば読める。
2. **`$HOME` 側の秘密情報**は、chezmoi の age 暗号化 (`encrypted_` の付いた source) で置く。
3. **システム側の秘密情報** (推論 API の鍵など) は、`*.age` を decman の宣言から復号し、権限 0600 のファイルとして置く。
4. **age の秘密鍵** (identity) は git に置かない。Desktop では `/root` と `~/.config/chezmoi/` に置く。ゼロから再現するとき (FLX-3) は、パスワードマネージャから手で戻す。
5. **受け手を秘密ごとに絞る。** Desktop の age 鍵で復号できるのは、Desktop が使う秘密だけにする。Server 用の秘密は Desktop の鍵を受け手に入れない。dotfiles は公開リポジトリなので暗号文は誰でも取れる。Desktop の鍵が漏れたときに読まれる範囲を、Desktop の秘密に限るためである。
6. 平文が混ざらないように、既存の gitleaks (pre-commit) を使い続ける。
7. **持ち出されたとき**は `runbooks/credential-revocation.md` に従って失効・交換する (ADR-0007 でディスクを暗号化しないため)。

## 満たす制約

| ID | どう満たすか | 根拠 |
|---|---|---|
| SEC-2 | 宣言リポジトリには暗号文だけを置く。平文の混入は gitleaks で止める | chezmoi docs (age 暗号化)、dotfiles の運用原則 |

## 満たせない制約と妥協

なし。

## トレードオフ

- **得るもの:** OS に依存しない。今の鍵を使い回せる。
- **失うもの:**
  - age の秘密鍵を手で戻す手順が、ゼロからの再現 (FLX-3) に1つ加わる。
  - agenix にあった「起動時に復号して tmpfs に置く」仕組みは無くなり、復号したファイルはディスクに残る。ディスクは暗号化しない (ADR-0007) ので、持ち出しへの備えは失効手順書で代える。

## 切り替えトリガー

| 条件 | 切り替え先 |
|---|---|
| システム側の秘密情報が5つを超える | sops (extra) に移し、ファイル単位でなく値単位で管理する |

## 検証

- 機能テスト `doctor/secrets`: 秘密情報のファイルが存在し、権限が 0600 で、git の管理下に平文が無いことを確かめる。Desktop の鍵で復号できる `*.age` が、失効手順書の表に載っているものだけであることも確かめる (段階4)。
