# ADR-0006: ディスクは by-id で指定し、検査を通してからインストールする

日付: 2026-10-24。状態: 承認 (2026-10-24)。

## 文脈

- SAF-1 (MUST): 消去や初期化は対象を一意の ID で指定し、別のディスクを誤って消さない。
- archinstall の `disk_config` の `device` は、文書の例では `/dev/sda` のような名前で書く。ソースを読むかぎり、読み込み時に検出したデバイスの辞書をそのパスで引き、見つからなければその項目を**黙って飛ばす** [推論。実機では未検証]。`/dev/disk/by-id/...` を書いたときに一致するかも確かめていない。
- `/dev/nvme0n1` や `/dev/sda` は、起動ごとに入れ替わることがある (カーネルの名前は永続しない) [一般的な事実。udev の文書による]。
- FLX-3 (SHOULD): 空のディスクから1時間以内に再現する。

## 決定

1. **ディスクの宣言は1か所に置く** (`install/disks.toml`)。各ディスクについて次を書く。
   - `/dev/disk/by-id/` のパス
   - シリアル番号と容量 (期待値)
   - 役割 (system / data)
2. **消去する操作は、ラッパースクリプトの1つの関数からだけ行う** (`install/wipe.sh` の `wipe_declared`)。この関数は次を確かめてから消す。
   1. by-id のパスが存在し、ちょうど1つのブロックデバイスに解決されること。
   2. `lsblk` で読んだシリアル番号と容量が、宣言と一致すること。
   3. マウントされていないこと。
   4. 最後に、解決した `/dev/...` と宣言を画面に出し、入力で確認すること (無人のときは、環境変数で明示した ID と一致すること)。
3. **archinstall には、解決した直後の `/dev/...` を渡す**。設定ファイルは実行の直前に生成し、そこで渡すデバイスは1台だけにする。archinstall の中で消去されるのは、この1台に限られる。
4. **HDD** は archinstall に渡さない。初期化はインストール後に、同じ `wipe_declared` を通して行う。
5. **ゼロからの再現手順** (FLX-3):
   1. ISO で起動する (ADR-0007 により Secure Boot は無効)。
   2. `install/bootstrap.sh` を実行する。中身は disks の検査 → archinstall → 初回起動で decman → `chezmoi init --apply` → age の秘密鍵を戻す。
   3. 機能テストの Launch を通す。

## 満たす制約

| ID | どう満たすか | 根拠 |
|---|---|---|
| SAF-1 | 消去の入口を1つにし、by-id の解決・シリアル番号・容量・マウント状態を確かめてから消す。archinstall には1台しか渡さない | archinstall のソース (facts-arch)、D-V4 の静的検査 |

## 満たせない制約と妥協

| ID | 満たせない部分 | 妥協の理由と手当て |
|---|---|---|
| FLX-3 (部分) | 1時間に収まるかは計測していない。ネットワークの速さ (CUDA のイメージ、モデル) に依存する。age の秘密鍵は手で戻す | まず VM で計測する (代用と明記する)。モデルは REL-4 の対象外 (再取得できる) とし、時間の計測には含めない |

## トレードオフ

- **得るもの:** 消去の対象を取り違える経路を1つに絞れる。その経路を静的に検査できる (D-V4)。
- **失うもの:**
  - archinstall の対話的な使い方はできない。
  - スクリプトを1つ自分で保守する。

## 切り替えトリガー

| 条件 | 切り替え先 |
|---|---|
| archinstall が by-id を直接受け付け、見つからないときにエラーで止まるようになる | ラッパーの解決処理を外し、by-id を直接渡す |
| ADR-0001 で OS を替える | その手段のインストーラで、by-id による指定と「見つからなければ止まる」動作を確かめる (例: disko、kickstart、Agama) |

## 検証

- D-V4: `install/` 以下のスクリプトで、消去・初期化のコマンド (`wipefs`、`sgdisk`、`mkfs.*`、`blkdiscard`、archinstall) を呼ぶ箇所が、`wipe_declared` の中だけにあること。そこに渡る値が `disks.toml` の by-id から来ることも静的に検査する (段階3)。
- 機能テスト `drive/install-from-zero`: VM に宣言と違うディスクを付けて、ラッパーが止まることを確かめる (壊した版)。そのうえで、宣言どおりのディスクに入れて所要時間を測る (段階4、代用)。
