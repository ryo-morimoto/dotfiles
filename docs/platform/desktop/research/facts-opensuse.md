# openSUSE (Tumbleweed / transactional 系) の事実 (取得日 2026-10-24)

## 候補の定義

- **D: openSUSE Tumbleweed (通常の読み書きルート)**。btrfs + snapper (zypper の pre/post スナップショット)。ブートローダは GRUB2 か systemd-boot (sdbootutil)。宣言の道具は標準では無いので、汎用ツール (metapac / Ansible / Salt) と chezmoi を組み合わせる前提で調べた。NVIDIA は OSS の署名済み open kmp と、NVIDIA リポジトリのユーザ空間ドライバを組み合わせる。
- **D': transactional 系**。(a) Tumbleweed と同じ OSS リポジトリを使う MicroOS (読み取り専用ルート + transactional-update) の上にデスクトップを載せる構成、(b) Aeon (GNOME) / Kalpa (MicroOS ベースのデスクトップ)、(c) 通常の Tumbleweed で transactional-update を使う構成。
- 第三の候補 (blendOS、Vanilla OS、KDE Linux など) は調べていない (後述)。

確認の方法: パッケージの有無は、`download.opensuse.org/tumbleweed/repo/oss` の primary.xml (2026-10-24 時点、snapshot 20261021) と、OBS の各リポジトリの repodata を直接取得して確かめた。

## 未検証のまま残したこと

- fcitx5-hazkey、zen、quickshell が、OBS の誰かの home / devel プロジェクトにあるか。OBS の検索 (software.opensuse.org、build.opensuse.org) がこの環境から取得できなかった (403 か robots)。src.opensuse.org (Factory の git) と OSS には無いことは確かめた。
- 署名済みの open kmp を、Secure Boot を有効にした実機で MOK を登録せずに読み込めるか。署名者が openSUSE Secure Boot CA であることまでは確かめた。それを明記した openSUSE の公式文書は見つからなかった (SDB:NVIDIA_drivers は open ドライバに触れていない)。
- openQA が NVIDIA ドライバ (kmp と NVIDIA リポジトリのユーザ空間) を試験しているか。NVIDIA リポジトリは Tumbleweed のスナップショットの公開の流れの外にあり、OSS の kmp と版がずれることがある (取得時点でもずれていた)。そのとき zypper がどう解決するかは試していない。
- GRUB の場合、`/boot` のカーネルがロールバックで戻るかを、公式文書の明示的な記述では確かめていない (サブボリュームの一覧から推論した)。
- systemd-boot (sdbootutil) が Tumbleweed で今も「experimental」扱いか。wiki のページの日付は確かめていない。インストーラの既定が systemd-boot になっていることは確認済み。
- systemd-boot で、スナップショットごとのカーネルを置くと ESP の容量が足りるか。
- Tumbleweed で手動介入を告知する頻度と、週あたりの保守時間 (MNT-4)。
- OBS の home リポジトリが関わったサプライチェーン事件の公式記録。探していない。
- 第三の候補 (blendOS、Vanilla OS、KDE Linux など)。ブリーフの「無理に探さなくてよい」に従い調べていない。
- openSUSE wiki の Portal:Tumbleweed と openSUSE:Tumbleweed_process は、この環境から取得できなかった (client_error)。代わりに Factory_development_model と release-tools の文書を使った。
